# User Manual with Screenshots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An interactive, bilingual HTML user manual of the walkthrough path, with a real annotated
screenshot of the portal for every step, regenerated by one command.

**Architecture:** A Playwright "journey" drives the whole path against a freshly reset local stack
and writes JPEG screenshots plus a `manifest.json` (hotspot boxes in % of the image) per language.
A Node generator turns `user-manual.md` (Markdown with a few conventions) and the manifest into an
HTML fragment in the guides' design, with the interactive layer (role filter, progress, hotspots,
lightbox, tabs, search, deep links, print) as inline CSS/JS. Hotspots are HTML buttons over clean
images (not burned in), so they are clickable and accessible; only secrets are blurred into the
image.

**Tech Stack:** Playwright (already in `apps/web`), Node 24 ESM scripts, Vitest (`vitest run --dir scripts`), axe (`@axe-core/playwright`, already present). No new dependencies.

**Spec:** [docs/superpowers/specs/2026-11-19-user-manual-design.md](../specs/2026-11-19-user-manual-design.md)

## Global Constraints

- Official docs in English with the Spanish version at the same path under `docs/es/`, in the same commit (ADR-0027). UI default Spanish.
- Only synthetic data; no PII; QR codes, client secrets and enrollment tokens blurred in the image.
- Example values per language = that language's walkthrough: provider *Civil Registry* / `civil-registry` / NIT `900000100`; consumer *Ministerio de Bienestar de Wakanda* (en: *Ministry of Welfare of Wakanda*) / `bienestar-wakanda` / NIT `900000200`; API *Certificado de afiliación* (en: *Affiliation certificate*) / `certificados-afiliacion`.
- Node and API values follow the fixtures: node service path `/salud`, contract `infra/mock-providers/salud/openapi.yaml`, lookup `/afiliados/{id}`, record `1000000001`. The manual calls them example values.
- Screenshots: viewport 1440×900, scale 1, `type: 'jpeg', quality: 85`, cropped to the relevant region; target ≈ 2–4 MB per language. Committed to git.
- Images: `docs/es/guides/img/user-manual/` (Spanish UI) and `docs/guides/img/user-manual/` (English UI), same file names; `manifest.json` beside them.
- Text stands without the image; alt text ≤ 155 characters; captions carry explanations; no text burned into screenshots; no video/GIF; hover-only interactions forbidden (WCAG 1.4.13); WCAG 2.1 AA.
- The manual is public (GitHub Pages): no demo deployment domain, real people or real entities.
- No new dependencies. Commit locally only (no push). Conventional Commits in English.

## Review Focus

1. Running the capture on a stack that already has `civil-registry` → it stops before any screenshot with "reset the stack first (pnpm docs:manual --yes)" instead of failing half-way with a duplicate-slug error. *(Task 3 test `refuses a stack that already has the manual's entities`.)*
2. A figure in the Markdown whose id is missing from the manifest, or whose hotspot count differs from its sub-steps → the generator exits non-zero naming the id; it never emits a figure without its image. *(Task 4 tests.)*
3. `localStorage` unavailable (private window, file://, blocked) → the page renders and every control works, only memory is lost. *(Task 5 test `works when storage throws`.)*
4. Keyboard only → every hotspot, tab, the lightbox (Esc closes, focus returns to the image) and the role filter are operable. *(Task 5 test `keyboard-only use`.)*
5. Phone width (390 px) → no horizontal page scroll, hotspots stay on their elements (positions in %). *(Task 5 test `phone width`.)*

### Task 2: Capture toolkit (`shot`, manifest, i18n, people)

**Files:**
- Create: `apps/web/e2e/manual/playwright.manual.config.ts`, `shots.ts`, `i18n.ts`, `people.ts`, `toolkit.manual.ts`
- Modify: `apps/web/playwright.config.ts` — `testIgnore: ['manual/**']` so `pnpm test:e2e` never runs them.

**Interfaces:**
- Produces:
  - `type Lang = 'es' | 'en'`; `const lang: Lang` (from `process.env.MANUAL_LANG`, default `'es'`).
  - `t(lang: Lang, key: string): string` — dotted key into `apps/web/messages/<lang>.json`; throws on a missing key.
  - `localePath(lang: Lang, path: string): string` — `'/en' + path` for English, `path` for Spanish (`localePrefix: 'as-needed'`).
  - `shot(page: Page, id: string, opts: { hotspots?: Locator[]; blur?: Locator[]; region?: Locator; pad?: number }): Promise<void>` — scrolls `region` (default: the `main` element) into view, blurs `blur` (`filter: blur(8px)`), screenshots the region's box plus `pad` (default 16) clipped to the viewport, as JPEG q85 to `imgDir(lang)/<id>.jpg`, records every hotspot's box in % of the image, restores the blur.
  - `imgDir(lang): string` — `docs/guides/img/user-manual` (en) or `docs/es/guides/img/user-manual` (es), absolute.
  - `writeManifest(): void` — writes `imgDir(lang)/manifest.json`: `{ lang, shots: { [id]: { file, width, height, hotspots: Array<{ n: number; x: number; y: number; w: number; h: number }> } } }` (n from 1, values in %, 2 decimals, ids sorted).
  - `interface Person { key: string; username: string; email: string; firstName: string; lastName: string; password: string; totpSecret?: string; page?: Page }`; `PEOPLE: Record<'rosa'|'diego'|'tomas'|'wanda', Person>` per the shot list.
  - `register(browser: Browser, p: Person): Promise<Page>` — own context with `locale` = lang, Keycloak registration + Mailpit verification (reuse `waitForMail` from `../onboarding`), returns the signed-in page and stores it in `p.page`.
  - `enrollTotp(page: Page, p: Person): Promise<void>` — like `enrollOneTimeCode` in `../helpers` but stores `p.totpSecret` from `#totpSecret`.
  - `ensureSignedIn(p: Person, path: string): Promise<Page>` — goes to `localePath(lang, path)`; if Keycloak's login appears, fills username, password and `totp(Date.now(), p.totpSecret)` (reuse `totp` from `../helpers`).
- Config: projects `journey` (`testMatch: 'journey.manual.ts'`, webServer as the main config, `globalSetup` none — the capture script migrates/seeds), `toolkit` (`toolkit.manual.ts`) and `page` (`page.manual.ts`, no webServer). `use.viewport` 1440×900, `locale` from lang, `workers: 1`, `timeout: 1_800_000` for journey.

  - Consecutive fenced blocks with info `<lang> tab="<label>"` → one tab group (`role="tablist"`), each panel a terminal block with a copy button.
  - Every `##`/`###` gets a "copy link" button.
